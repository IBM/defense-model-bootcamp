## ⏳ Waiting: Model Comparison in Progress

After clicking **RUN COMPARISON** in Step 1, ARGUS AI begins evaluating all 13 questions against both models. The page transitions to a **Processing Model Comparison** screen — do not close or refresh the page while it runs.

![Processing Model Comparison screen showing 4-step progress tracker at 5%](/img/lab-03/step2_1.png)

The progress tracker shows four sequential stages:

1. **Loading validation dataset** — The uploaded CSV is parsed and questions are queued
2. **Running Model 1 predictions** — Each question is sent to the Fine-tuned Model and the predicted category is recorded
3. **Running Model 2 predictions** — The same questions are sent to the Base Model
4. **Generating comparison metrics** — Accuracy scores, category breakdowns, error listings, and the performance delta are calculated

The full run typically takes **15–30 seconds**. When complete, you will be automatically taken to the results dashboard.

    <p><strong>1. Classification Inference</strong></p>
    <p style={{marginLeft: '20px'}}>Each question from the evaluation CSV is sent to both models as a prompt. Each model returns its predicted category label (e.g., <code>equipment</code>, <code>inventory</code>, <code>installations</code>).</p>

    <p><strong>2. Ground-Truth Comparison</strong></p>
    <p style={{marginLeft: '20px'}}>The predicted category is compared against the correct category label in the CSV. A match counts as correct; a mismatch is recorded as an error.</p>

    <p><strong>3. Metric Aggregation</strong></p>
    <p style={{marginLeft: '20px'}}>Results are aggregated per category and overall. Overall accuracy, category-wise accuracy, error count, and the performance delta between models are all calculated.</p>

    <p><strong>4. Report Generation</strong></p>
    <p style={{marginLeft: '20px', marginBottom: 0}}>The dashboard you will see in Step 3 — including the score cards, bar chart, performance radar, category details, and key insights — is assembled from these aggregated results.</p>

## 💡 Pro Tips for Evaluation Runs

<div style={{
  display: 'grid',
  gridTemplateColumns: 'repeat(auto-fit, minmax(280px, 1fr))',
  gap: '16px',
  margin: '24px 0'
}}>
  <div style={{
    background: '#D0E2FF',
    padding: '20px',
    borderRadius: '4px',
    borderLeft: '4px solid #0F62FE'
  }}>
    <h4 style={{marginTop: 0, color: '#0353E9'}}>✅ Best Practices</h4>
    <ul style={{marginBottom: 0, paddingLeft: '20px', color: '#161616'}}>
      <li>Always use held-out questions the model has never seen</li>
      <li>Include enough examples per category to get a reliable accuracy reading</li>
      <li>Run the same evaluation dataset against multiple model versions to track improvement over time</li>
      <li>Keep the page open until the run finishes</li>
    </ul>
  </div>

  <div style={{
    background: '#FFE6E6',
    padding: '20px',
    borderRadius: '4px',
    borderLeft: '4px solid #DA1E28'
  }}>
    <h4 style={{marginTop: 0, color: '#A2191F'}}>❌ Common Mistakes</h4>
    <ul style={{marginBottom: 0, paddingLeft: '20px', color: '#161616'}}>
      <li>Using training data as evaluation data — this inflates scores and hides real performance</li>
      <li>Evaluating on too few questions per category (fewer than 5 makes accuracy unreliable)</li>
      <li>Refreshing the page mid-run — this cancels the comparison and requires restarting</li>
      <li>Comparing different model versions across different evaluation datasets</li>
    </ul>
  </div>
